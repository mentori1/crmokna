# CRM «Овсянников»

CRM для бизнеса по продаже окон, стройматериалов и товаров для ремонта.
Заменяет ведение в Google Таблице: централизует заказы, клиентов, оплаты,
доставку и финансы. Чистый фронтенд (HTML + CSS + ванильный JS, без сборки),
данные — JSON-файлы, подтягиваются из рабочей Google Таблицы.

- **Демо:** https://mentori1.github.io/crmokna/ (логин ниже, данные обфусцированы)
- **Репозиторий:** `git@github.com:mentori1/crmokna.git`
- **Локально:** двойной клик по `Открыть CRM.command`

## 2. Как открыть локально (одна кнопка)

Дважды кликните по файлу **`Открыть CRM.command`** в папке проекта.

Автоматически: обновит данные из Google Таблицы → поднимет локальный
веб-сервер (встроенный Python, ничего ставить не нужно) → откроет браузер.

Откроется окно терминала — **оставьте его открытым** (в нём работает сервер),
можно свернуть. Закроете окно — CRM выключится.

> Первый запуск: macOS может заблокировать «неизвестного разработчика» —
> ПКМ по файлу → «Открыть» → «Открыть». Нужно один раз.

**С телефона** (в той же Wi-Fi сети): открыть `http://<IP-компьютера>:3457`.
Либо использовать демо на GitHub Pages — она доступна с любого устройства.

⚠️ **Нельзя** открывать `index.html` двойным кликом напрямую — браузер откроет
его как `file://`, и данные не загрузятся («Failed to fetch»). Только через
сервер (`.command` или GitHub Pages).

### Распознавание заказов
У старых заказов есть номер в столбце «№», у новых (с 2023 г.) — нет. Поэтому
строка считается заказом **по наличию даты**, а не номера (иначе терялись бы
тысячи заказов). Нет номера → присваивается технический `ЗК-NNNNN`.

### Демо-данные
`import/make_demo_data.py` заменяет реальные ФИО/телефоны клиентов на
выдуманные (структура заказов, суммы и поставщики сохраняются — для
убедительности демо). Реальные данные перед этим бэкапятся в
`data_real_backup/` (тоже в `.gitignore`). Вернуть реальные:
`python3 import/sync_sheets.py`.

## 4. Разделы CRM

| Раздел | Что показывает | Действия |
|---|---|---|
| **Дашборд** | Заказы, выручка, прибыль за период; долги; последние заказы; графики | Кнопки периода: 30 дней / Квартал / Полгода / Год / Всё время |
| **Заказы** | Все заказы (пагинация по 50), фильтр по статусу и датам | Открыть карточку, создать, редактировать, **добавить платёж** |
| **Доставка** | Только открытые заказы и статусы их доставки | Сменить статус доставки, клик по строке → карточка заказа |
| **Клиенты** | Список с суммой покупок и задолженностью | Карточка с историей заказов |
| **Поставщики** | Список с суммой закупок и долгом перед ними | Карточка с заказами |
| **Финансы** | Выручка, прибыль, дебиторка, кредиторка; движение денег | Фильтр по типу/датам, **+ Операция** |
| **Склад** | Карточки товаров, остатки | **+ Товар**, **Приход** |

### Период на дашборде
Кнопки **30 дней / Квартал / Полгода / Год / Всё время** пересчитывают
*заказы, выручку и прибыль* за окно от сегодня назад. Долги клиентов и
поставщиков всегда показывают **текущий остаток** (не зависит от периода).

### Статусы заказа
Новый → В работе → Заказан у поставщика → Получен на склад → Доставляется →
Доставлен → Закрыт. Меняются в карточке заказа.

### Статусы доставки (раздел «Доставка»)
Не назначен → Машина едет за грузом → Груз отгружен → Груз на складе →
Отправлен клиенту → Получен клиентом. Меняются прямо в карточке.
*(В планах: автозаполнение из почты.)*

## 5. Работа с заказом

**Новый заказ** (кнопка «+ Новый заказ»):
- ФИО клиента — поле с автоподсказками; можно вписать **нового** клиента;
- Телефон, дата создания/доставки, адрес;
- **Продукция** — свободный ввод названия + кол-во + закупка + продажа;
  несколько позиций кнопкой «+ Добавить позицию»;
- **Размеры** — поле появляется автоматически, если в названии есть
  «окно/дверь/балкон/стекло/подоконник/откос/витраж/…» (см. `SIZED_KEYWORDS`);
- Поставщик — с подсказками, можно вписать нового.

Новые клиенты и поставщики создаются автоматически при сохранении
(`findOrCreateClient` / `findOrCreateSupplier`).

**Редактирование:** открыть заказ → «✏ Редактировать» — те же поля.

**Добавить платёж:** в карточке заказа блок «Добавить платёж» — сумма, тип
(от клиента / поставщику), описание. Клиент платит частями — каждый платёж
отдельной строкой; прогресс-бар и долг пересчитываются сразу. Платёж попадает
в раздел «Финансы» с привязкой к заказу и контрагенту.

### Сквозная синхронизация
Любое изменение (платёж, новая операция, товар, смена статуса) сразу
пересчитывает открытый раздел через `rerenderActiveSection()` — метрики,
долги и таблицы везде остаются согласованными.

> Важно: правки в CRM живут в браузере и **перезаписываются при следующей
> синхронизации** из Google Таблицы. Источник истины — таблица. Двусторонняя
> запись (CRM → Таблица) — следующий этап.

## 7. Мобильная версия

Интерфейс адаптирован под телефон (брейкпоинты ≤860px и ≤560px):
- Боковое меню прячется в бургер с затемнением;
- Модалки — с отступами по краям, скруглением, высота `100dvh` (низ не прячется
  под адресной строкой Safari);
- **Таблицы превращаются в карточки** — каждая строка показывает поля сверху
  вниз (подпись слева, значение справа), без горизонтального скролла. Реализовано
  через `data-label` на каждом `<td>` + CSS-трансформация в `@media ≤560px`;
- Поля форм 16px (iOS не зумит), `input[type=date]` с `-webkit-appearance:none`
  (иначе на iOS выезжают за рамки).

⚠️ **Кэш на телефоне:** при обновлениях версия файлов растёт (`?v=N` в `index.html`),
обычно подтягивается само. Если видно старое — потяните страницу вниз для
обновления или переоткройте вкладку.

## 9. Модель данных и связи

```
clients ──1:N── orders ──1:N── items (продукция) ──N:1── suppliers
                  │
                  └── transactions (приход от клиента / расход поставщику)
```

Поля заказа: `order_number`, `client_id`, `status`, `delivery_status`,
`created_at`, `delivery_date`, `notes`, `items[]`.
Позиция (`item`): `product_name`, `dimensions`, `supplier_id`, `quantity`,
`purchase_price`, `sale_price`.

Расчёты (`calcOrder`):
- Маржа = (Σ продажа) − (Σ закупка);
- Долг клиента = сумма продажи − полученные оплаты (income-транзакции заказа);
- Долг поставщику = сумма закупки − оплачено поставщику (expense-транзакции).

`schema.sql` — эквивалентная схема PostgreSQL на случай переноса на сервер.

## 10. Если что-то не работает

| Проблема | Решение |
|---|---|
| «Failed to fetch» / нет данных | Открыли `index.html` напрямую — запускайте через `.command` или Pages |
| CRM не открылась | Закройте окно терминала, снова запустите `Открыть CRM.command` |
| Данные устарели | Перезапустите через `.command` (синхронизация при старте) |
| «нет сети» при синхронизации | Откроются последние сохранённые данные; повторите при интернете |
| Порт 3457 занят | Скрипт сам убивает старый процесс и поднимает заново |
| Ошибка доступа к таблице | Таблица должна быть расшарена на `mentori@sanya-498120.iam.gserviceaccount.com` |
| На телефоне старый вид | Кэш — потяните вниз для обновления / переоткройте вкладку |
| Не пушится на GitHub | SSH-ключ должен быть добавлен в аккаунт: `ssh -T git@github.com` |

## 11. Разработка и деплой

- Правка кода → **поднять `?v=N`** в `index.html` (для `style.css` и `app.js`),
  иначе пользователи получат старую версию из кэша.
- Залить: `git add -A && git commit -m "…" && git push origin main`.
- GitHub Pages пересобирается за ~30–60 сек после push.
- Перед пушем `data/*.json` сбрасываются к демо (`git checkout HEAD -- data/`),
  чтобы не залить тестовые правки или реальные данные.
