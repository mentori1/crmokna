# Интеграция с производством по почте — спецификация

Автоматизация: CRM ↔ производство через электронную почту, движок — **n8n**,
хранилище связок и статусов — **Google Таблица** (та же `Baza_Ovsyannikov`).

Статус: **Этап 1 (фронт CRM) готов.** Этапы 2–4 — по мере подключения почты,
n8n и получения образцов писем от производства.

---

## 1. Потоки данных

```
СОЗДАНИЕ ЗАКАЗА
  Менеджер в CRM → заказу присвоен CRM-ID (CRM-00092)
  Кнопка «Сформировать заявку» → письмо с CRM-ID в теме и теле
        ↓ (Этап 3: автоотправка через n8n; сейчас — вручную mailto/копипаст)
  Производство получает заявку

ОТВЕТ ПРОИЗВОДСТВА (письмо / Excel)
  n8n IMAP мониторит ящик
        ↓
  Поиск CRM-ID (regex)  ─── нашёл ──→ сопоставление с заказом
        │                              сохранение номера пр-ва: CRM-00092 ↔ 785412
        │                              обновление статуса
        └─ не нашёл ──→ матч по номеру пр-ва (если связка уже есть)
                    └─ Excel-вложение → парсинг строк → матч по CRM-ID/номеру
                          └─ не распарсилось → ИИ (Claude) извлекает структуру

ЗАПИСЬ РЕЗУЛЬТАТА
  n8n → Google Таблица (колонки ниже) → CRM читает при синхронизации
```

---

## 2. Структура Google Таблицы (новые колонки)

В лист «Заказы» (или отдельный лист `production`) добавить:

| Колонка | Назначение | Кто пишет |
|---|---|---|
| `CRM-ID` | Стабильный идентификатор заказа (`CRM-00092`) | CRM при создании |
| `Номер производства` | Внутренний номер от производства (`785412`) | n8n |
| `Статус производства` | `sent / accepted / in_progress / shipped / delivered` | n8n |
| `Дата обновления статуса` | Когда пришло последнее обновление | n8n |
| `Источник` | `email-reply / excel / ai` — откуда взят статус | n8n |

> **Важно про стабильность CRM-ID:** сейчас в коде CRM-ID выводится из `o.id`
> (`crmId()` в `app.js`), а `o.id` переприсваивается при каждой синхронизации
> из Таблицы. Для надёжной долгосрочной связки CRM-ID должен стать **постоянной
> колонкой** в Таблице, присваиваемой один раз. Это часть Этапа 2 (двусторонняя
> запись). До тех пор связки нестабильны между пересинхронизациями.

## 3. Формат письма-заявки

Генерируется в `buildProductionEmail()` (`app.js`).

**Тема:** `Заявка CRM-00092 — <первый товар>`
**Тело:**
```
Здравствуйте!

Просим принять в работу заказ.

Идентификатор заказа: CRM-00092
Дата: 01.06.2026
Клиент: <имя>

Состав заказа:
  1. <товар> | размеры: 1400×1300 | кол-во: 2

Просьба в ответном письме указать ваш внутренний номер заказа
и сохранить идентификатор CRM-00092 в теме для автоматического учёта.
```

**Regex для поиска CRM-ID** в любом тексте (тема/тело/Excel-ячейка):
```
CRM-\d{4,6}
```

## 4. n8n — воркфлоу

### 4.1. Исходящий (отправка заявки) — Этап 3
- **Триггер:** webhook от CRM (`POST /production-request` с `{crm_id, subject, body}`)
  ИЛИ Google Sheets trigger на новую строку со статусом «Новый».
- **Узлы:** Set (тема/тело) → SMTP (отправка на адрес производства).
- Адрес производства: зашить в воркфлоу или хранить в карточке поставщика.

### 4.2. Входящий (обработка ответов) — Этап 3
- **Триггер:** IMAP Email (мониторинг ящика, каждые N минут).
- **Ветвление по содержимому:**

  **A. Есть CRM-ID в теме/теле** (`CRM-\d{4,6}`):
  1. Найти строку в Таблице по `CRM-ID`.
  2. Извлечь номер производства из тела (regex под формат производства,
     напр. `№\s*(\d{5,7})` или «наш номер: 785412»).
  3. Записать `Номер производства`, `Статус производства`, дату, источник=`email-reply`.

  **B. Есть Excel-вложение** (см. 4.3):
  1. Скачать вложение → n8n **Spreadsheet File** node → массив строк.
  2. Для каждой строки: найти `CRM-ID` или `Номер производства` → матч заказа.
  3. Извлечь статус из колонки статуса → нормализовать (см. 5) → записать.

  **C. Нет ни CRM-ID, ни структуры** → ветка ИИ (4.4).

### 4.3. Парсинг Excel
- n8n node **Spreadsheet File** (читает .xlsx/.xls/.csv) → JSON-строки.
- Сопоставление колонок — **по образцу реального файла** (нужны примеры!).
  Ожидаемые колонки: `[CRM-ID | Номер заказа] , [Статус] , [Дата]`.
- Нормализация статуса по ключевым словам (см. 5).

### 4.4. ИИ-резерв (только если не распарсилось) — Этап 4
- Узел HTTP Request → Claude API (Anthropic).
- Промпт: «Извлеки из письма список {crm_id|номер_производства, статус}.
  Верни строго JSON. Если данных нет — пустой массив.»
- Модель: `claude-haiku-4-5` (дёшево/быстро) с фолбэком на `claude-sonnet`.
- Результат валидируется (JSON-схема) перед записью в Таблицу.
- **ИИ не основной путь** — только когда regex/Excel не сработали.

## 5. Нормализация статусов производства

Ключевые слова из писем → статус CRM:

| Слова в письме | `Статус производства` | Влияние на доставку CRM |
|---|---|---|
| принят, в работу, подтверждаем | `accepted` | — |
| изготавливается, в производстве | `in_progress` | — |
| отгружен, отгрузка, передан в доставку | `shipped` | → `delivering` |
| доставлен, выдан, получен | `delivered` | → `delivered` |

(Маппинг — `PRODUCTION_STATUS_LABELS` в `app.js`.)
