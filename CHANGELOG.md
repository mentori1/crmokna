## Данные — 2026-07-01 — Объединение клиентов по имени
- Второй проход дедупа (после телефонного): склейка записей одного человека,
  вбитых по-разному по ИМЕНИ (разный порядок слов + лишние слова/адрес/цифры:
  «Женя Смольников» = «Смольников Женя» = «Женя Смольников, кедрал» = …).
- Правило безопасное: совпадение по ТОЧНОМУ набору слов-имён (мусор-слова —
  товары/материалы/улицы/родство — выкидываются списком NOISE), минимум 2 слова,
  без транзитивных цепочек — разные люди не смешиваются (Вова Мельник ≠ Женя
  Мельников; Дима Райвио ≠ Дима Сороло). Группы с ≥2 разными телефонами
  пропущены на ручную проверку (20 шт).
- Итог: 234 склейки, 367 записей подтянуто к «главному», 436 заказов перенесено;
  главному ставится чистое имя. Ничего не удалялось. Скрипт:
  `scratchpad/merge_by_name.py`. Бэкап: `~/mentori-backups/.../2026-07-01_0543`.

## v26 — 2026-07-01 — Поиск клиента по номеру телефона (борьба с дублями)
- В форме заказа при вводе телефона (10 цифр) клиент ищется **по номеру**, а не
  по имени: менеджеры пишут имя по-разному (Женя / Евгений / Евгеша), номер один.
  Под полем телефона подсказка: «Найден в базе: <имя> · заказов: N» или
  «Новый номер — клиента в базе нет».
- При совпадении номера имя и адрес клиента подставляются автоматически.
- **Главное — новые дубли больше не плодятся**: `findOrCreateClient` сначала
  ищет по номеру и переиспользует существующего клиента, даже если имя ввели
  иначе. Если под номером несколько записей — берётся «главная» (больше всего
  заказов, при равенстве — меньший id).
- Нормализация номера (`normPhone`) — сравнение по 10 цифрам, независимо от
  формата записи (8/+7/скобки/пробелы).
- **Разовое объединение истории:** заказы и платежи, оформленные на один номер
  под разными именами (231 номер, 333 записи), перенесены на одного «главного»
  клиента по номеру — теперь при открытии клиента видны ВСЕ его заказы.
  329 заказов перенесено, все 4942 заказа на месте, ничего не удалялось
  (записи клиентов сохранены). Скрипт: `scratchpad/merge_dupes.py` (repoint-only),
  бэкап перед операцией: `~/mentori-backups/ovsyannikov-crm/2026-07-01_0426`.
- **Чистка имён (по согласованию):** 45 «главных» записей-адресов переименованы
  в нормальные ФИО, взятые из вариантов того же номера (напр.
  «Садовая 17-57,Олег Нифакин» → «Олег Нифакин»). Чистые имена не трогались,
  правились только записи с цифрами/адресом. Скрипт `scratchpad/rename_canon.py`.

## v25 — 2026-07-01 — Fix: в «Доставке» не менялся статус вручную
- Симптом: тап по выпадающему списку статуса доставки открывал карточку заказа
  вместо смены статуса (особенно на телефоне) — казалось, что статус не поменять.
- Причина: клик по строке всегда открывал карточку; `stopPropagation` на списке
  не всегда перехватывал тап на сенсорных экранах.
- Фикс: обработчик строки теперь игнорирует клики по списку статуса
  (`.delivery-select`), а перерисовка отложена (`setTimeout 0`), чтобы нативный
  список на телефоне успел зафиксировать выбор. Клик по остальной части строки
  по-прежнему открывает карточку. Проверено: смена статуса сохраняется в Supabase.

## v24 — 2026-07-01 — Поставщики: добавление/редактирование + удобство телефона
- **Поставщиков теперь можно добавлять и редактировать.** Кнопка «+ Новый
  поставщик» раньше висела без обработчика (ничего не делала), а карточка была
  «только для чтения». Добавлены форма (название, контактное лицо, телефон,
  email), сохранение в Supabase, кнопка «Изменить» в строке и «Редактировать»

- **Телефон подставляет +7 сам.** Во всех полях телефона (новый заказ,
  редактирование заказа, поставщик) номер форматируется на лету в
  `+7 (XXX) XXX-XX-XX`: если начали с 8 — меняется на 7, если ввели без кода
  страны — 7 добавляется автоматически.
- **Автозаполнение при выборе клиента из базы.** Если в заказе выбрать
  существующего клиента, его телефон и адрес (если сохранены) подставляются
  автоматически. Адрес, введённый в заказе, теперь сохраняется клиенту —
  и в следующий раз подставится сам. (У импортированных клиентов адресов пока
  нет, поэтому адрес накапливается по мере ввода; телефон подставляется сразу.)

  исправлена потеря ~3127 заказов (фильтр по дате вместо номера). Итог:
  **4941 заказ, 2021–2026, выручка ~151 млн ₽, прибыль ~34 млн ₽**.
- **Поле «Размеры»** в позициях заказа — авто-появление для окон/дверей и т.п.
- **Добавление платежей** в карточке заказа (клиент платит частями) +
  кнопки «+ Операция» (Финансы), «+ Товар» / «Приход» (Склад).
- **Раздел «Доставка»** со статусами доставки открытых заказов.
- **Ручной ввод** клиентов/поставщиков/продукции (свободный ввод + автосоздание).
- **Период на дашборде** (30 дней / Квартал / Полгода / Год / Всё время).
- Первичный импорт из CSV → переход на XLSX (реальные даты) → на API.
