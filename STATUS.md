# Статус проекта CRM «Овсянников» — что готово / что осталось

Аудит на 2026-06-16 (методики: code-to-prd — инвентарь реализованного,
tech-debt-tracker — приоритеты недоделок). Версия фронта: `v=14`.

**Кратко:** UI и бизнес-логика **готовы и работают** (7 разделов, расчёты,
карточки, мобильная версия, демо на GitHub Pages). Главное ограничение —
**CRM пока read-only**: правки живут только в памяти браузера и не сохраняются
обратно в источник. Это блокирует реальную эксплуатацию и почтовую автоматику.

## ✅ РЕАЛИЗОВАНО (по факту в коде)

### Разделы (7)
| Раздел | Что умеет |
|---|---|
| **Дашборд** | Метрики за период (30д/квартал/полгода/год/всё), выручка/прибыль/долги, последние заказы, графики (выручка по месяцам, заказы по статусам) |
| **Заказы** | Список + пагинация по 50, фильтр по статусу/датам, карточка, создание, редактирование, **платежи частями** |
| **Доставка** | Открытые заказы + статусы доставки (6 статусов), клик → карточка |
| **Клиенты** | Список с суммой покупок и долгом, карточка с историей заказов |
| **Поставщики** | Список с суммой закупок и долгом, карточка |
| **Финансы** | Выручка/прибыль/дебиторка/кредиторка, движение денег, фильтры, + Операция |
| **Склад** | + Товар, Приход (UI готов, **данных нет** — см. ниже) |

### Сквозные возможности
- **Глобальный поиск** по заказам (номер, CRM-ID, клиент, телефон, продукция,
  номер производства), клиентам, поставщикам *(был баг с ложными результатами
  при текстовом поиске — исправлен в v15)*;
- **Расчёты** (`calcOrder`): маржа, маржинальность, долг клиента, долг поставщику;
- **Статусы**: заказа (7), доставки (6), производства (5) — enum-словари;
- **Ручной ввод**: новые клиенты/поставщики/продукция создаются автоматически;
- **Поле «Размеры»** для окон/дверей (авто-появление по ключевым словам);
- **Сквозной пересчёт** разделов после любого изменения;
- **Мобильная версия**: бургер-меню, модалки с отступами, таблицы→карточки;
- **Авторизация** (логин-экран на публичной версии);
- **Производство Этап 1**: CRM-ID, блок «Производство» в карточке, генерация
  письма-заявки (тема+тело с CRM-ID), копировать / открыть в почте.

### Данные и деплой
- Источник: Google Таблица → `import/sync_sheets.py` → `data/*.json` (read-only fetch);
- **4941 заказ, 3024 клиента, 118 поставщиков, 9061 транзакция** (2021–2026);
- Демо на GitHub Pages (обфусцированные данные), реальные — локально;
- Запуск одной кнопкой (`Открыть CRM.command`).

## ⚠️ ОГРАНИЧЕНИЯ И ТЕХДОЛГ (по приоритету)

### 🔴 CRITICAL — блокирует реальную работу
1. **Нет обратной записи данных.** Ни одного POST/append — создание заказа,
   платёж, смена статуса, новый товар сохраняются **только в памяти браузера**.
   После перезагрузки или следующей синхронизации — теряются. Источник правды
   (Google Таблица) не обновляется из CRM.
   → *Пока это «просмотрщик с временными правками», а не операционная CRM.*
2. **Демо-данные на проде.** Публичная версия (Pages) показывает выдуманные
   данные. Реальные доступны только локально и не защищены за серверной авторизацией
   (клиентский логин обходится через DevTools). Для реальной эксплуатации нужен сервер.

### 🟠 HIGH — нужно для заявленных целей
3. **Производство, Этапы 2–4** (активный запрос бизнеса). Фронт (Этап 1) готов,
   но нет: отправки писем, IMAP-приёма ответов, парсинга Excel, ИИ-резерва.
   Статусы/номера производства некому записывать. Спец — `INTEGRATION.md`.
4. **CRM-ID нестабилен** между синхронизациями (выводится из `o.id`, который
   переприсваивается). Для надёжной связки `CRM-ID ↔ номер производства` нужен
   постоянной колонкой в Таблице. Зависит от п.1.
5. **Синхронизация односторонняя и ручная** (читает таблицу при запуске). Нет
   автообновления по расписанию.

### 🟡 MEDIUM
6. **Склад пустой** — `products=[]`, нет номенклатуры/остатков. Раздел работает,
   но данных нет (в таблице нет товарного учёта).
7. **Нет ролей/прав** — один пользователь, все действия доступны всем.

### 🟢 LOW
8. Бэкап правок, экспорт отчётов, печать заказа, push-уведомления о доставках.

## 🗺️ ПЛАН РАБОТ ПО ЭТАПАМ

Этапы упорядочены по зависимостям: каждый следующий опирается на предыдущий.

### Этап A — Сервер + обратная запись (фундамент) 🔴
*Снимает CRITICAL-долг №1, №2. Без него остальное не имеет смысла.*
- Перенос на сервер (запущен пользователем), серверная авторизация;
- Двусторонняя связь: CRM → запись в Google Таблицу (или БД по `schema.sql`);
- CRM-ID как постоянная колонка (фикс долга №4).

### Этап B — Производство по почте 🟠
*Опирается на A. Реализует ключевую бизнес-цель. ТЗ — `INTEGRATION.md`.*
- Поднять n8n, подключить почтовый ящик;
- Исходящее: автоотправка заявки с CRM-ID;
- Входящее: IMAP → матчинг по CRM-ID → запись номера/статуса производства;
- Парсинг Excel-файлов от производства;
- ИИ-резерв (Claude) для неструктурированных писем.
- *Нужно от владельца:* почтовый ящик, адрес производства, образцы писем/Excel.

### Этап C — Автоматизация и склад 🟡
- Автосинхронизация по расписанию (cron/n8n);
- Наполнение склада (если появится товарный учёт);
- Роли/права при многопользовательском доступе.

### Этап D — Полировка 🟢
- Экспорт/печать заказа и отчётов, бэкап, уведомления о ближайших доставках.

## Ближайший шаг
**Этап A** (сервер + обратная запись) — он разблокирует всё остальное.
Сейчас пользователь как раз переносит проект на сервер — логично на этой базе
сразу делать обратную запись, иначе данные продолжат теряться.
